# OpenYASKE UI 監査（2026-11-03）

対象は Kotlin Multiplatform + Compose Multiplatform の現行 `master`。コードは変更していない（読解のみ、ビルド未実行）。

パスの略記:

- `composeApp/…` = `kmp/composeApp/src/commonMain/kotlin/org/openyaske/app/…`
- `core/…` = `kmp/shared/src/commonMain/kotlin/org/openyaske/core/…`
- `wasm/…` = `kmp/composeApp/src/wasmJsMain/…`
- `android/…` = `kmp/composeApp/src/androidMain/…`

読んだもの: unslop の SKILL と signs、`docs/visual-spec.md`、`docs/original-ui-inventory.md`、`docs/architecture-review.md`、`App.kt` と `ui/` 以下（`design/`、`strings/`、`timetable/`、`calendar/`）、`/data/artifacts/openyaske-screens/`、共有コアの `CoreApi`・`ScheduleService`・`CourseService`・`SyllabusCatalog`・モデル。

先に 3 点の前提を置く。

1. スクリーンショットは現行コードより古い箇所がある。ホームの設定ヘッダーが写っておらず、カレンダーは「帯」で描かれているが、コードは 6dp ドット（`composeApp/ui/calendar/MonthGrid.kt:171-191`）。判断はコードを正とした。
2. `LargeTopAppBar` は現行コードに存在しない。`grep -rn "TopAppBar" kmp` の結果は `AppBars.kt` の `TopAppBar` と、`MoreScreen`/`PdfScreen` の `scrollBehavior` のみ。CHANGELOG にある「その他を LargeTopAppBar 化」は、現行 `composeApp/ui/MoreScreen.kt:57-64` の 56dp `TabHeader` に置き換わっている。項目 3 はこの事実を踏まえて扱う。
3. レビュー結果は会話に無かったため、指摘はすべてコードとスクリーンショットから確認した。推測で項目は追加していない（台帳は 1〜41 のみ）。

## 総評

画面の骨格、色、寸法は `ui/design/Tokens.kt` にまとまっており、本家の見た目から出発した意図は読める。一方で、モデルとコア API が持っている機能（優先度・時刻・繰り返し・学期・出席・シナリオ・削除）に対して画面が追いついていない。今回の指摘の約 3 分の 1 は「コアにあるのに UI が繋がっていない」であり、これは画面の作り込み不足と、部品（行・シート・面）の共通化不足の 2 つに集約できる。

見た目の問題は 3 つ。角丸が 8/9/10/12/14/28/丸の 7 種に散っていること、白い面と地の使い分けがコードから読めないこと、文字が 139 箇所で直に `sp` 指定され type scale がほぼ使われていないこと（`MaterialTheme.typography` の参照は 3 箇所）。M3E を名乗るなら、ここを先に決めないと各画面の修正が積み上がらない。

## 台帳

### 1. 起動スプラッシュ

- 画面: 共通（Web 起動 / Android 起動）
- 現状のコード根拠: `wasm/index.html:16-25`（`#boot` は文字だけ。`.done` で `opacity: 0` にするが要素は残す）、`:51`（`OpenYASKE` の 1 行）、`:66-74`（最初の canvas を 60ms 間隔で見て消し、8 秒で強制終了。進捗表示なし）。`android/AndroidManifest.xml:6` は `Theme.Material.Light.NoActionBar` のみでスプラッシュ無し。Compose 側に起動中 UI は無い（`composeApp/App.kt:56-63` はシラバス読込を投げるだけ）。
- 何が問題か: 透過後も `#boot` のノードが DOM に残り、読み上げとテキスト選択の対象になる。読み込みの進み具合が見えず、フォントの差し替え（`composeApp/ui/Theme.kt:162-175`）で字が入れ替わる間も無表示になる。
- 直し方案: 案 A を推奨。`#boot` に `favicon.svg` のロゴ 48dp・地色・下端 2dp の不定プログレス（CSS の `translateX` アニメ）を置き、`transitionend` で `boot.remove()` する。文言は置かない（i18n キー不要）。案 B はスプラッシュ廃止で、`App.kt` のシラバス読込が終わるまで `TodayHero` と同じ 28dp 角丸・`primaryContainer` のスケルトン 1 枚を出す。Android は `androidx.core:core-splashscreen` の `installSplashScreen()` と `Theme.SplashScreen`（`windowSplashScreenAnimatedIcon=@mipmap/ic_launcher`）を追加する。ロゴは既存の `app_icon` と `favicon.svg` を使う。
- 影響範囲: `wasm/index.html`、`MainActivity`、Android テーマ、配布物
- 難易度: S
- 他項目との依存: 13・20 の色と角を先に決めると二度手間にならない

### 2. 通知と PWA

- 画面: 共通（設定 / Web）
- 現状のコード根拠: 通知は UI とモデルだけ。`composeApp/ui/SettingsScreen.kt:163-178` のトグル、`core/api/AppSettings.kt:20,47` の `NotificationSettings`。実行系は無い（`grep -rni notification kmp` は UI・モデル・文言のみ。`POST_NOTIFICATIONS`、`WorkManager`、`AlarmManager` は 0 件）。Web は `wasm/index.html:1-48` に manifest も service worker も無く、`theme-color` は固定。
- 何が問題か: トグルを動かしても何も起きない。PWA としてインストールできず、再訪のたびに wasm と 9.2MB のフォントを取り直す。
- 直し方案: 通知は「入れる」か「消す」かを決める。入れる場合、Android は `WorkManager` の定期実行と `NotificationManagerCompat`（`leadMinutes` 前、`quietDuringClass` を尊重）、Web は通知トリガー API が未成熟なので保留と明記する。消す場合は設定の節と `NotificationSettings` を UI から外す。PWA は `wasm/resources/manifest.webmanifest`（`display: standalone`、`start_url: /`、192/512 のアイコンを `apple-touch-icon.png` から生成）、`sw.js`（`composeApp.js`、`.wasm`、`composeResources/**` を stale-while-revalidate）、`index.html` に `link rel=manifest` と `navigator.serviceWorker.register` を追加。
- 影響範囲: Android の依存とマニフェスト、wasm 配布物、設定文言 4 言語
- 難易度: L（通知） / M（PWA）
- 他項目との依存: 15・16 の締切時刻と 21 の学期日付が決まらないと通知時刻を計算できない

### 3. 横画面でヘッダーが表示領域を削る

## M3E の観点で共通に直すべき土台

以下 5 つ。画面ごとの修正より先に決める。数値は提案で、決めた時点で `Tokens.kt` に固定する。

### F1. アプリバーと画面骨格

現状は 56dp 固定の `TabHeader` が 5 画面に散り、カレンダーだけ独自 `Row`、More と PDF は `TopAppBar` 系と混在している。左右のスロット数も画面ごとに違う。

決めること: 高さ 56dp（縦）/ 44dp（横・高さ 480dp 未満）、左 40dp スロット、中央は `weight(1f)` の中央寄せ、右は 40dp の倍数。`AppTopBar` と `TabHeader` の 2 種に絞り、`ScreenHeader`（`ui/design/Navigation.kt:140-183`）は廃止する。大型アプリバーを使う場合も、横画面では常に畳んだ 56dp にする。

参照: 3、5、33

### F2. タイポグラフィのロール化

`fontSize` の直書きが 139 箇所、`MaterialTheme.typography` の参照は 3 箇所、`FontWeight.Bold` が 31 箇所。11sp と 12sp と 13sp が同じ重みで並び、階層がサイズだけで決まっていない。

決めること: 画面で使うロールを 6 つに限定する（`titleLarge` 20/画面名、`titleMedium` 16/節、`bodyLarge` 15/本文、`bodyMedium` 14/行、`bodySmall` 12/補助、`labelSmall` 11/メタ）。太字は `SemiBold` まで。数値は `tabular-nums` 相当（`TextStyle(fontFeatureSettings = "tnum")`）。直書きをロールに置換し、`grep "fontSize =" kmp/composeApp` が 0 件になるのを完了条件にする。

参照: 4、10、13、19、20

### F3. 角丸・面・塗りのトークン

角丸が 7 種、白面の使われ方が 3 通り（全幅の行、角丸カード、透明セル）、`primaryContainer` と科目色 16% が同じ強さで並ぶ。

決めること: `Radius` を control 10 / card 16 / sheet 28 / pill 50% の 4 段にし、`MaterialTheme.shapes` と一致させる。面は 3 種（地 `background`、面 `surface` + 1dp `border`、強調 `primaryContainer`）に限定し、科目色は 16%（暗所 24%）だけ。直値の `RoundedCornerShape(n.dp)` を 0 件にする。

参照: 13、20、24、26、28

### F4. 遷移と戻るの階層

タブは `pushState` で履歴を積み、シートとダイアログは履歴に参加せず、`BackHandler` はタブのルートでも消費する。この 3 つが噛み合っていない。

決めること: 「タブ = 履歴 1 段」「詳細 = 履歴 1 段」「シート/ダイアログ = 履歴を増やさず、`BackHandler` を 1 枚積む」。`popstate` を購読して URL から状態を復元する。`ModalHost` を 1 つ作り、全シートをそこに通す。

参照: 12、22、31、32、39、41

### F5. 余白・密度・横画面

4dp グリッドは守られているが、カード内の余白が 12/14/18、画面下の余白が 88/96/110/150 とばらつく。横画面の分岐はカレンダーだけ。

決めること: 画面端 16dp、カード内 16dp、行の高さ 56dp、節の上 24 / 下 8、画面下は「ナビ 80 + 16」の 96dp に統一する。`maxHeight < 480dp` を横画面コンパクトとして `CompositionLocal`（`LocalCompactLayout`）で配り、ヘッダー・下部余白・列数を一括で切り替える。ホームの「今日 / 今後」2 列はこの分岐の中で選ぶ。

参照: 3、9、18、30、33
